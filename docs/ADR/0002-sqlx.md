# ADR 0002 — Use SQLx as Database Library

- **Status**: Accepted
- **Date**: 2026-01-01
- **Author**: ChamathDilshanC

---

## Context

The backend requires a PostgreSQL client that supports async queries, compile-time SQL verification, complex migrations, and pgvector extension queries. We need raw SQL access for advanced features (window functions, CTEs, `<=>` vector distance operators, `tsvector` search).

Candidates evaluated:
- **SQLx** — async, compile-time checked SQL
- **Diesel** — sync ORM, compile-time schema
- **SeaORM** — async ORM on top of SQLx
- **tokio-postgres** — raw async driver

---

## Decision

**Use SQLx with `query_as!` macros for all database operations.**

---

## Rationale

| Criterion | SQLx | Diesel | SeaORM |
|-----------|------|--------|--------|
| Async-native | ✅ Yes | ❌ Blocking | ✅ Yes (via SQLx) |
| Compile-time SQL check | ✅ Via macros | ✅ Via DSL | ❌ No |
| Raw SQL support | ✅ Full | ⚠️ Limited | ⚠️ Limited |
| pgvector operators | ✅ Raw SQL | ❌ Not supported | ❌ Not supported |
| tsvector / tsquery | ✅ Raw SQL | ❌ Not supported | ❌ Not supported |
| Migration tool | ✅ sqlx-cli | ✅ diesel_cli | ✅ sea-orm-cli |
| Learning curve | Low | Medium | Medium |

**Key factor**: pgvector's `<=>` cosine distance operator and PostgreSQL FTS require raw SQL. SQLx is the only mature option that gives compile-time query verification without hiding raw SQL.

---

## Consequences

- All queries must use `sqlx::query_as!` or `sqlx::query!` macros.
- No raw string SQL formatting (SQL injection prevention).
- The `DATABASE_URL` environment variable must be set at compile time for macro verification.
- Migrations managed via `sqlx migrate` CLI in `migrations/`.
- Connection pooling via `sqlx::PgPool` — no alternative pool libraries.
- **Do not introduce Diesel, SeaORM, or any other ORM.**
